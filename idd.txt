### 4. Handwritten System Flow (Financial Software Requirements)

From the diagram, the proposed system seems to include:

**Core Modules / Features**:
- **Student Management**: Add Student (Name, Adm No, Class/Stream, Phone, Status - Day/Boarding, etc.)
- **Fee Payment**:
  - Search by Adm No / Name
  - Record payment (Amount, Term, Date, Mode)
  - Balance calculation (Current term + Arrears from previous years)
- **Fee Structure Management**:
  - Define vote heads per term/year
  - Generate fee structure per student (Day vs Boarding)
- **Receipt Generation**:
  - Official receipt printing with breakdown
  - Sequential receipt numbering
- **Reports**:
  - Fee balance per student
  - Term balance / Arrears
  - Overall school collection
- **Other**:
  - New year carry-over (balance from last year)
  - Installation / Users / Security

**Data Flow Sketch**:
1. Add Student → 
2. Search Student → 
3. Pay Fees (select term/vote heads) → 
4. Update Balance → 
5. Generate Receipt → 
6. Reports / Fee Structure updates

- **Database Tables** needed:
  - `students` (adm_no, name, class, stream, boarding_status, phone, etc.)
  - `fee_structures` (year, term, vote_head, amount_day, amount_boarding)
  - `payments` (receipt_no, student_id, date, amount, term, mode, vote_head_breakdown)
  - `fee_balances` (student_id, term, current_due, arrears, total_balance)
